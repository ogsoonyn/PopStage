# 決めたことの経緯

ルールそのものは `CLAUDE.md` と `.claude/rules/` にある。ここには、なぜそう決めたかと、いつ決めたかを残す。新しいものを下に足す。見出しは「日付 内容(PR / Issue)」の形にする。

## 2026-11-10 開発を始める

- 手元の設計書とブラウザ版のモックを元に作り始めた。当初は Godot 4 + C# の予定だったが、ブラウザ版のモックで中核の体験が成り立ったので、TypeScript + three.js + Vite(UI は Tailwind + daisyUI)に切り替え、モックを土台に育てた。モックはその後、リポジトリから消した。
- 揺れの物理は、今の手法で一から作った。
- ライブラリや実行環境は、確認を取ってから入れることにした。このとき承認したのは three、fflate、mediabunny、gifenc、vite、typescript、@types/three、tailwindcss、@tailwindcss/vite、daisyui、vitest、@playwright/test。Playwright のブラウザはダウンロードせず、手元の Chrome を使う。
- 設定の「陰影」は品質が良くなかったので消した。
- リポジトリを公開するにあたり、README から手元の環境に依存した記述を消した。ライセンスは MIT にした(著作権者は GitHub のアカウント名)。コードのコメントにあった「設計書◯章」の参照も整理した。

## 2026-11-10 手元の動作確認サーバーのフリーズ

- 手元の 5173 のサーバーがときどき固まった。原因は次の3つだった。
  - エージェントの E2E が CPU を使い切っていた(SwiftShader の Chrome で、コア約 8.5 本ぶん)。
  - 作業ツリーを編集するたびに、HMR でページ全体が読み込み直されていた。
  - ワークツリーから立てた Vite が、共有のキャッシュ(`node_modules/.vite`)を作り直していた。
- そこで、作業はワークツリー・別ポート・別キャッシュで行うことにした。パフォーマンスのデバッグ表示(`?debug`)もこのとき足した。

## 2026-11-12 UI 構成の見直し(Issue #33〜#49、PR #50〜#52)

- 画面の要素の id、コマンドとショートカット、ツールを、それぞれ1か所の表にまとめた(#42、#43、#46)。
- シートへ移す部品は `data-m-slot` の印で、スマホで隠す部品は `d-only` で決めるようにした(#44)。それまでは移す部品を PC の DOM の並びで、隠す部品を CSS の `:has()` で決めていたので、PC の作りを変えるとスマホの中身が黙って変わっていた。
- 同じ設定を出す部品どうしの同期を手で書いていたのをやめ、`App` のメソッドを通してモデルから表示を決めるようにした(#45)。スマホのボタンが右パネルの DOM を読み、合成イベントを送っていたため。
- 説明は「?」で開くことにした(#37)。長い説明を画面に並べると読みにくい、というのが元の方針で、ツールチップだけでは触って使う端末や読み上げに届かないため。
- 左のツールバーにツール以外の操作も置いているのは、そこが最も押しやすいから(#33)。ツールとその場で効く操作を、見た目で見分けられるようにした。
- 右パネルのタブを、効く範囲で分け直した(#34)。PC とスマホで分け方を揃えた(#39)。
- 画面の状態を `App` から分ける案(#47 の一部)は、変更が大きいわりに得るものが少ないので見送った。
- マージ先を `develop` にし、`main` へは `develop` からだけ入れることにした。直った Issue は、PR を書き添えて閉じてよいことにした。

## 2026-11-12 お気に入り(揺れと動きの組み合わせを残す)

- いい揺れ方を見つけたときに、ファイルを別名で保存すると同じ画像のファイルが増えるので、組み合わせ(パラメータ)だけを残せるようにした。
- ブラウザに覚える「自分のプリセット」(1レイヤーの揺れを、ほかの絵でも使う)も考えたが、やりたいことではなかったので作らなかった。いい動きは絵(塗った形・ポップ量)と組みで意味があるので、`.pukupop` の中に入れ、ファイルを持っていけばほかの端末でも使えるようにした。
- 中身は全レイヤーのポップ量・重ね方・揺れ、自動揺らし、操作の記録(キーフレームを含む)、視点。画像とウェイトは入れない。視点はほかの視点の操作と同じく、アンドゥには積まない(画角だけはアンドゥできる)。
- 記録は書き換えないので、お気に入りと今の記録は同じものを指してよく、保存でも1回だけ書く。

## 2026-11-12 塗るときに重ね表示を自動でONにする

- 塗っても重ね表示が切れていると、どこを塗ったか分からないため。塗り始めではなく、塗るツールを選んだ時点で入れる(塗る前から塗り具合が見えるように)。
- 塗るツールから離れても自動では切らない。表示が勝手に切り替わる回数を減らすため。見栄えの確認は「表示クリア」で切る。
- 起動時に前回のツールを戻すときと、スマホから PC の幅に戻って PC のツールを戻すときは入れない(前回OFFにした表示を保つため)。同じツールを選び直したときも入れない(手で切った表示を戻さない)。新しい画像を開いてブラシにしたときは入れる(スマホは「つかむ」のままなので入れない)。
- 自動ONの入・切は、表示の設定と同じ prefs の `view` に `autoOverlay` として覚える。既定はON。

## 2026-11-12 複数のレイヤーをまとめて変える・重ね表示を3つにする

- 仕様は単一 HTML の試作で触って決めた。選び方は一覧での複数選択(Ctrl / Shift、スマホは長押し)にした。「選択中 / 全レイヤー」の切り替えだけの案は一部だけを選べず、チェック列の案は表示のチェックとまぎらわしいため。
- ポップ量は「同じ値に揃える」ではなく比率で伸び縮みさせる。膨らみを高さを変えて別のレイヤーに作ったとき、差を保って全体を大きくしたいため。基準は一番高いレイヤーにした(最後に押したレイヤーにすると、それが 0px のときに比率が決まらず、1500px の上限とも合わせにくい)。材質などほかの項目は揃える。
- 変えた項目だけを書く。揺れの設定は `physics` にまとまっているが、1つ変えたときにほかの項目(揺らし方など)を最後に押したレイヤーの値で上書きしないよう、レイヤーごとに作る。
- 全レイヤー表示はレイヤーごとに色を分ける(1色・高さのヒートマップの案より、どこがどのレイヤーかと重なりが同時に見えるため)。選んだレイヤーを濃く、ほかを薄く出す。色は一覧の並びで決め、ファイルには保存しない。先頭は1枚だけ重ねていたころの色。
- 表示のチェックは、選んでいても押した1行だけに効かせる。並べ替えは1枚のときだけ。塗り・膨らみは最後に押したレイヤーだけ。
- 選び方は画面だけの状態で、アンドゥにもファイルにも入れない。重ね表示の「全レイヤー」は `view.overlayAll` として prefs に覚える。
- 一覧のポップ量の横に、重ね方をアイコンで出す(前は「最大 300」の文字)。

## 2026-11-12 README を使う人向けにする(PR #68 と続き)

- README が長く読みにくかったので、一から書き直した。主な機能は1項目1〜2文にし、細かい仕様はアプリ内の「?」とヘルプに任せた。
- README はリポジトリの入口としてそのまま見えるので、使う人向けにした。テスト、`main` への push で公開されること、アイコンの作り方、構成、画面まわりの定義の表は README から外し、`CLAUDE.md` と `.claude/rules/` へ移した。README の開発の話は、手元で動かすコマンドだけにした。
- 既知の制限を見直した。
  - 「ウェイトは 8 ビット」は消した。ポップ量の上限 1500px でも1段は約 6px で、段差が目立つ場面が限られるため。
  - 「揺れはレイヤー単位」は、制限というより使い方のこつなので、主な機能の中に「別々に揺らしたい所はレイヤーを分ける」として書いた。
  - 「透過画像を横から見ると縁が引き伸ばされる」は残し、起きる条件と避け方を足した。頂点シェーダは頂点の位置でだけウェイトを読むので、ウェイトの境目はメッシュ1マス分の斜面になる。そこに不透明な輪郭が乗ると縦に引き伸ばされる。「アルファから生成」はウェイトの境目が輪郭に重なるので必ず起きる。
