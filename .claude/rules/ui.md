# 画面の作り

部品を足したり名前を変えたりするときは、README の「開発」の表に挙げた元のファイル(`src/ui/ids.ts` など)を先に直す。表の行が増えたら README も直す。

## 説明の出し方

- 長い説明を画面に並べない。読みにくくなるため。
- 項目の説明は「?」のボタンで開く。ツールチップ(`title`)だけに頼らない。触って使う端末や読み上げでは届かないため。
- ボタンの文言は短くし、状態は見出しの横に短く出す。

## 置き場所

- 左のツールバーは最も押しやすいので、ツールのほかに、よく使う操作も置く。そのぶん、ツールとその場で効く操作を見た目で見分けられるようにする。
- 右パネルのタブは、効く範囲で分ける。1つのタブの中で範囲を混ぜない。
- PC とスマホで、設定の分け方を揃える。

## スマホ

- スマホの部品は作り直さず、PC の DOM をシートへ移す。処理を PC と共通にするため。
- シートへ移す部品を DOM の並びで決めない。スマホで隠す部品を CSS の `:has()` で隠さない。

## 状態の変え方

- 同じ設定を複数の部品に出すときは、部品どうしで DOM を読んだりイベントを送ったりして同期しない。`App` のメソッド(`setLayerSwing` / `setAutoSwing` / `setPreset` など)を通し、モデルから表示を決める(Issue #45)。
- ショートカットは修飾キーまで含めて表に書く(`X` と `Shift+X` は別のキーとして扱われる)。
- 画面の状態(ツール・表示・ブラシ)を `App` から別のクラスへ分ける案は、変更が大きいわりに得るものが少ないので見送った(Issue #47)。新しい理由が無い限り、蒸し返さない。
