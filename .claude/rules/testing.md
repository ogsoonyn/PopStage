# テスト

E2E の流し方(ポート・設定ファイル・全件は最後に1回)は `CLAUDE.md` の「手元の動作確認を乱さない」にある。

- 単体テストは `tests/unit`、E2E は `tests/e2e` に置く。E2E は機能ごとにファイルを分け、共通の道具(起動・WebGL のエラーの見張り・3Dビューでのドラッグなど)は `tests/e2e/helpers.ts` にある。
- E2E はインストール済みの Google Chrome を使い(`channel: 'chrome'`)、描画は SwiftShader で行う(GPU が無くても動く)。
- 見た目の比較に使う基準画像は OS ごとに別のファイルになる。使っている OS 用のものが無いときは、`--update-snapshots` を付けて流して作る。

## E2E の書き方

- 新しく作る spec は、`tests/e2e/helpers.ts` の `boot()` で起動し、ファイルの先頭で `watchGlErrors()` を呼ぶ(WebGL のエラーで失敗にするため)。`mobile.spec.ts` と `take.spec.ts` は自前の `boot` を持つ例外で、GL のエラーを見張っていない。
- 右パネルの部品を触る前に、`openTab()` でその部品のタブを開く。

## クラウドと手元で流すテストを分ける

Claude Code のクラウド環境(`CLAUDE_CODE_REMOTE` がある。GPU が無く 4 コア)では、`playwright.config.ts` が 1 並列にし、`@local` の付いたテストを外す。自分の Playwright の設定は既定の設定を広げて作り(`{ ...base, ... }`)、`workers` と `grepInvert` を上書きしない。クラウドでも `@local` を流したいときは `E2E_ALL=1` を付ける。

2 並列では、直しても毎回別のテストがどれか落ちた(タップを 300ms 以内とみなす・ダブルタップ・止まった所の記録など、実時間に頼るもの)。1 並列で全件が約 10 分。1 並列でも、develop を取り込んだ後の1回で「揺らす」ツールとパフォーマンスのデバッグ表示が落ちたので、前者は `@local` にし、後者は確かめ方を直した。

- `@local` を付けるのは、クラウドではテストの書き方では直せないものだけ。今は4件: 中ドラッグで平行移動すると揺れる、右ドラッグで回しても・ホイールでズームしても揺れる、「揺らす」ツール(描画が 0.1 秒より遅いと視点の飛びとみなして揺らさない)、最近開いたファイルの場所を覚えて開き直す(クラウドの Chrome for Testing は、IndexedDB にファイルハンドルを入れるとブラウザごと落ちる)。付けるときは、テストの上に理由をコメントで書く。
- `@local` のテストは、手元(GPU のある PC)で流して確かめる: `npx playwright test --config <自分の設定> --grep @local`(クラウドで流すなら `E2E_ALL=1` も付ける。付けないと0件になる)。クラウドで `@local` を外した PR では、手元で流していないことを PR に書く。
- クラウドでは CPU が足りず、描画が 1 フレーム 0.1 秒を越えることがよくある。次のように書き、時間で待たない。
  - 状態が変わるのを待つときは、`waitForTimeout` の後に値を読まず、`expect(...).toBeChecked()` などの待つ形か `expect.poll` を使う。
  - 描画のフレームで反映されるもの(ウェイトの GPU への送り・画面)は、`nextFrames(page)` でフレームを進めてから見る。
  - 揺れは 1 フレームの dt を 0.1 秒で打ち切るので、描画が遅いと物理は実時間より遅れて進む。動きを一定の長さで測るときは、`popstage.world.time` で測る。
  - ズームなど数フレームかけて寄せる値は、`settled()` で止まるのを待つ。

## 過去に変更と関係なく落ちたテスト

次のテストは、変更と関係なく落ちたことがある。落ちたときは、`develop` のままでも落ちるか、単独で流して通るかを確かめてから判断し、PR に書く。PR #50〜#52 の全件の実行では落ちたという記録が無いので、もう直っているかもしれない。

- スマホの2本指タップで戻す: 全件や並列で流したときだけ落ち、単独では通った(PR #24、#28、#31)
- 「揺らす」ツール: ときどき落ちた(PR #21、#24)
- ピストン(画像全体が上下に動く): `develop` のままでも3回中2回落ちた(PR #31)
- 最近開いたファイル(場所を覚えて開き直す): 作業環境によっては `develop` でも落ちた(PR #21、#23、#29、#31)
- パフォーマンスのデバッグ表示: 作業環境によっては `develop` でも落ちた(PR #29)
- 画像を薄く: 一度落ち、流し直したら通った(PR #23)
- 中ドラッグで平行移動すると揺れる・右ドラッグで回してもホイールでズームしても揺れる: 4コアのクラウド環境では、`develop` のままでも単独でも落ちることがある。描画が 0.1 秒より遅いと視点の飛びとみなして揺らさないため(ズーム・回転の PR)
